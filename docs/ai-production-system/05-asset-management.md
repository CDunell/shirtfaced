# Asset Management

The future bottleneck is not generation. It is finding, trusting and reusing the correct asset later.

## Every source asset needs

- unique asset ID
- title
- world
- scene
- product status
- people status
- source prompt
- generator and model
- generation date
- approval state
- rejection reason if rejected
- permanent lesson if promoted
- parent asset
- derivative list
- aspect ratio
- crop-safe zones
- commercial-use notes
- linked campaign
- linked platform outputs
- Git or storage location

## Approval states

- generated
- shortlist
- approved source
- derivative in progress
- release ready
- published
- archived
- rejected

## Naming principle

File names must describe:
- world
- scene
- asset type
- version
- aspect ratio
- approval status

Avoid:
- final
- final-final
- new
- latest
- copy

## Prompt lineage

Every approved asset must retain:
- full prompt
- edits
- rejected versions
- model settings where available
- final adjustments
- resulting derivatives

Git stores the planning and decision history.
A DAM or structured storage system stores the heavy media and asset metadata.
