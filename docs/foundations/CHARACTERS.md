# SHIRTFACED — CHARACTERS

**Status:** Canon for what's actually decided below — the cast list and the scope rule.
Everything marked open is genuinely open, not a placeholder for an answer already chosen.

**Promoted from:** Hot List item 3 (`docs/shirtfaced-audit.md`, Area 1.1) — "there are no
characters, the biggest hole in the repo."

## 0. Scope & authority

`UNIVERSE_PREMISE.md`'s hierarchy puts characters above any single world: *"recurring
ordinary Australians whose lives continue across worlds."* This document is where
they live — portable, like `CARRY_FORWARD_CANON.md`, not World 01-specific.

**This is a story and continuity document, not prompt text.** `WORLD.md`'s own Form
rules say it directly: *"Name nobody. 'One bloke.' 'A woman.' 'Another mate.'"* That
rule doesn't change. A character here is never typed into a generation prompt by
name — the planner still gets "one bloke," "another mate." What this document is for
is recording which recurring person a given "one bloke" *is*, for continuity notes,
captions, and Identity-voice copy, tracked going forward via `CONTINUITY.md`'s Cast
Rotation table.

Visual identity consistency for a named character across independently generated
images is a harder, separate problem this document doesn't solve — see §3.

## 2. What's not decided yet

Everything below is genuinely open — not sketched, not implied, not derivable from
the name list itself:

- **Who's core and who's occasional.** The audit recommends 6–10 recurring people;
  fifteen were supplied. Whether that means a smaller core group with the rest
  appearing situationally, all fifteen recurring equally, or something else, hasn't
  been decided.
- **Relationships.** Nothing here establishes who's dating whom, who's related to
  whom, or how any of these fifteen know each other beyond "the group."
- **Individual roles or bits.** `studio/docs/stage-2/CHANNEL_TRANSLATION.md` §6
  already names a set of recognisable recurring social roles for micro-story
  content — the drinks carrier, the snack thief, the "one beer" person, the missing
  mate, the charger seeker, the borrowed-hoodie friend, the one refusing to end the
  night. That's an available vocabulary for *whoever* assigns roles, later — it is
  not an assignment of any of these fifteen people to any of these roles. Do that
  when a specific scene or piece of content actually needs one of them to carry a
  bit; inventing it ahead of that need is exactly the kind of fabrication this
  document got rewritten to remove.

## 3. What this doesn't solve

Two more things this document deliberately leaves open:

- **Visual consistency.** Nothing here guarantees a named character looks like the
  same person across two independent generations. That's a reference-image-
  conditioning problem (see `reference_active_limit` in Studio's config), not a
  story problem, and it isn't solved by naming him.
- **Casting.** `docs/SESSION_HANDOVER_2026-08-07.md` §9 names casting rules and
  "designing for the photograph someone else takes" as live, unresolved strategic
  questions. This document gives future casting a name list to cast *for* — it
  doesn't answer who plays them.
