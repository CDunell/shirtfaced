# Shirtfaced

T-shirt storefront for **shirtfaced.wtf**. Next.js (App Router) + Tailwind CSS,
built as a static export — no server runtime at request time.

The product catalog is managed in [admin/](admin/) (Postgres-backed) and
pulled into this app at *build* time — see "Product catalog" below. The cart
is client-side only (React context backed by `localStorage`, see
`src/lib/cart-context.tsx`) — there is no checkout/payment integration yet.

## Develop

```bash
npm install
cp .env.example .env   # SHOP_DATABASE_URL — see "Product catalog" below
npm run dev
```

Open http://localhost:3000.

## Build

```bash
npm run build
```

`prebuild`/`predev` refresh `src/lib/products-data.generated.ts` from
Postgres first (see below). Emits a static site to `out/`. Deploys as-is to
Cloudflare Pages, Netlify, Vercel, or any static host — no server runtime
required.

## Product catalog

`src/lib/products.ts` holds the types, size chart and helper functions —
those are still hand-written. The actual product data
(`src/lib/products-data.generated.ts`) is generated by
`scripts/sync-products.mjs` from the **same Postgres database the admin app
writes to**, using a read-only role (`shirtfaced_readonly`). It runs
automatically before `dev`/`build`.

If `SHOP_DATABASE_URL` isn't set, the sync step is a no-op and the
last-generated file (checked into git as a fallback snapshot) is used as-is
— a fresh clone without DB access still builds.

**This means editing a product in admin does not update the live site
instantly** — the static export only reflects whatever the catalog looked
like at the last build. Publishing is now automatic on every push to `main`
(see "Deploying" below), so in practice this means: admin edits show up on
the next deploy, not the next request.

## Deploying

`.github/workflows/deploy.yml` runs on every push to `main`: it rsyncs
`admin/` and this storefront to the Oracle box
(`/home/ubuntu/shirtfaced-admin`, `/home/ubuntu/shirtfaced-site`), then runs
`~/deploy-admin.sh` / `~/deploy-site.sh` on the box over SSH — `npm install
&& npm run build`, then either a systemd restart (admin) or an `rsync` into
`/var/www/shirtfaced` (storefront, served directly by nginx, no restart
needed).

Studio deploys in the same run, to `/home/ubuntu/shirtfaced-studio`, using the
scripts in [studio/deploy/](studio/deploy/). Two differences from the other two:

- **`worlds/` is synced with `--ignore-existing`, not `--delete`.** Studio writes
  canon there when a shot is approved, so the box owns that directory. New world
  files reach it; nothing on it is ever overwritten from here. The corollary is
  that editing canon locally does *not* update the box.
- **`.env` is written once by `bootstrap-studio.sh` and never replaced.** The
  OpenAI key is placed only into an empty slot, from the `OPENAI_API_KEY` repo
  secret, so a deploy without that secret cannot blank a working key. With no key
  at all Studio runs its deterministic fakes and bills nothing.

Studio listens on loopback only and is reached at `studio.shirtfaced.wtf`
through the Cloudflare Tunnel. It has no login of its own: it verifies the
session cookie admin signs, using the same `SESSION_SECRET`, so being signed
into admin is being signed into Studio. That matters because its generate
endpoint spends money.

Prompts are written in Studio, not in admin. Admin links to it and nothing more.

Auth is a dedicated deploy key (`ORACLE_DEPLOY_KEY` / `ORACLE_HOST` repo
secrets), kept separate from any personal key so it can be revoked on its
own. Note it isn't lower-*privilege* than a personal key would be — the
`ubuntu` account on the box has an unrestricted sudo grant from Oracle
Cloud's own provisioning — just independently revocable.

To deploy by hand instead (e.g. to debug a failed run):

```bash
ssh ubuntu@<host> 'bash /home/ubuntu/deploy-site.sh'   # or deploy-admin.sh
```

Each app's `.env` on the box lives only there (never synced from CI) — the
workflow's rsync excludes it.

## Structure

- `src/app/page.tsx` — home page / product grid
- `src/app/products/[slug]/page.tsx` — product detail + add to cart
- `src/app/cart/page.tsx` — cart page
- `src/app/checkout/page.tsx` — checkout (no card fields by design)
- `src/lib/products.ts` — types, size chart, helpers (hand-written)
- `src/lib/products-data.generated.ts` — catalog data (generated, see above)
- `src/lib/cart-context.tsx` — cart state

## Admin

`admin/` is a separate server-rendered Next.js app for managing the shop's
product catalog and inventory against Postgres — the storefront above stays
a static export with no database. See [admin/README.md](admin/README.md) for
local setup and how it's deployed. It links out to Studio from its nav, but
the two don't share a runtime, database, or toolchain.

## Studio

`studio/` holds the build pack for **Shirtfaced Studio** — a separate
local-first Python/FastAPI + PostgreSQL app for producing the brand's
photographic worlds. Start at [studio/README.md](studio/README.md). It does not
share a runtime, a database or a toolchain with the storefront above, and it
deploys to the same box (see "Deploying").
