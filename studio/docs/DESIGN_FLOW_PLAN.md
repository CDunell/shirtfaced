# The product design flow: a phased plan

**Status:** rewritten 2026-08-14 against `PIPELINE_AUDIT_2026-08-14.md`, the
two-pipeline split, and the ten-step sequence in
`SHIRTFACED_PRODUCT_DESIGN_CONSTITUTION.md`.

**Scope: the product pipeline only.** World, socials and marketing belong to
`admin.shirtfaced.wtf` and get their own plan. Nothing here touches them except
Phase 2, which moves them out.

`docs/shirtfaced-audit.md` is a guideline for direction; it predates the vintage
subsystem and one of its factual claims is corrected in the 14 August audit.

---

## The rule everything is judged against

> At every point there is **exactly one obvious next action**. Doing it reveals
> the next. Following that chain to a finished design requires no knowledge of
> which screen owns what.

## Phase 0 — two decisions, no code

Neither is mine to make and both block work behind them.

**0.1 — What "generated by this app" means.** Hot List #1 requires a design
generated by this app. Paid subscriptions already cover generation and an API
key bills separately, so wiring it charges twice. Proposed reading: *the app
owns the brief, record, measurement, judgement and decision; the pixels are made
in a paid interface and brought back.* Reject this and local generation goes
ahead of everything.

**0.2 — Where the scorecard lives.** `design_scoring.py` was deleted per §8 of
the adaptation doc, so judgement now runs through
`admin/src/design-system/workflow.ts`. By the two-pipeline split, admin is the
world tool — so the product judgement engine sits in the wrong building. Either
it moves to studio, or admin is accepted as a shared service and the split is
restated. Phase 1 needs the answer.

---

## Phase 1 — make the chain continuous

*One design, concept to approved version, without a terminal.*

Six things, in order. Each is small; together they are the whole gap between
concept and approved version.

1. **A research concept can become a design concept.** Today the backlog is only
   reachable through `concept_importer` reading a Markdown file. Ten researched
   concepts cannot become ten backlog concepts.
2. **Artwork can be attached to an attempt.** `uploadAsset()` exists and no
   screen calls it. A drop zone on the attempt.
3. **Measurement attaches to the attempt.** `/api/design/score` takes a file and
   references no attempt, so a measurement persists nowhere. It becomes
   something an attempt does to its own artwork.
4. **The nine categories can be answered.** The blocking gap. A form for
   *validate recognition*, *validate production* and *review against the
   collection* — the constitution's steps 7, 8 and 9, kept as three groups
   rather than one undifferentiated list, because they are three different
   questions.
5. **Print reads the approved version.** `printing.py` holds no reference to
   `approved_designs`; the approved artwork should be Print's input rather than
   a file dragged in by hand.
6. **Every screen states its next action.** Plain sentences on the attempt, not
   inferred from state.

**Exit test — run and pasted:**

> A person who has not used the tool takes one research concept to a persisted
> approved design version and a printed mockup, without being told which screen
> to visit and without a terminal. `score_design()` receives a complete
> `DesignReviewInput` and stores a decision.

That is the audit's Hot List #1, met for the first time.

**Known limitation, stated deliberately:** a design completed in Phase 1 is
mechanically complete, not constitutionally complete. Steps 1–4 of the sequence
arrive in Phase 4. Phase 1 buys a working chain, not a compliant one.

## Phase 2 — separate the two pipelines

Prompts, Social, Email and the world Dashboard leave Studio for Admin. Studio
keeps evidence, research, concepts, design, compose, score and print.

Done before the Work screen so that screen is built in a product-only tool and
never has to explain why a photography shot is in a product queue.

**Exit test:** Studio's navigation contains only product destinations, Phase 1
still passes, and nothing that moved is unreachable in Admin.

## Phase 3 — one record, one screen

A `ProductionItem` carrying the design concept, its research provenance, the
attempt, the approved version, and a **derived** `next_action` — computed from
rows that already exist so it cannot drift from them.

**Work** replaces the Dashboard: items, each showing its next action as a button
that goes straight there. Nothing else on it.

**Exit test:** the entire Phase 1 flow is driven from Work without touching the
top navigation.

## Phase 4 — the constitution's first four steps

The four decisions that precede artwork and currently have no representation in
software:

1. define the product
2. define its role in the range — Anchor / Core / Expression / Hero / Collaboration
3. select the garment architecture
4. select the graphic architecture — the A1–A8 archetypes

`design_advisor` already answers 3 and 4 from 12,151 measured images and nothing
calls it. This is mostly wiring, not building.

Typography — the constitution's step 6 — is added here too. It has no step, no
service and no field today, and it is what made the first two test renders fail.

**Exit test:** an attempt cannot be opened without a collection role and a
graphic archetype recorded, and the advisor's recommendation is visible at the
moment those are chosen.

## Phase 5 — consolidate the design journey

Designs becomes the one screen; Compose becomes a generation method inside it
and Score an evaluation panel inside it. Both leave the navigation. Services
stay where they are — the duplicate is the journey, not the code.

**Exit test:** two navigation entries removed, no capability lost, Phase 1 still
passes.

## Phase 6 — evidence reaches generation

Vintage evidence informs the prompt text and never reaches the image generator;
it is stored on the attempt as provenance only. The `ReferenceImageStore`
adapter exists and runs in production for photography.

Depends on 0.1: doing this without a metered API means local generation.

**Exit test:** an attempt records which evidence images were sent, and the
output carries the era rather than a generic reading of it.

## Not started before Phase 3 passes

Campaign and drop orchestration, video as a first-class asset, the storefront
handoff, social rendering consolidation, reporting, operational health, the
confirmed fossils, `taglines.ts` deriving from `BRAND_VOICE.md`, and the world
pipeline's own gaps — a cast the code can read, a video path, a line to the
customer.

## How this gets worked

- **One phase at a time, in order.**
- **Every phase ends with its exit test run and pasted**, never asserted.
- **Nothing ships without being exercised in a browser.** Server checks have
  passed while a screen was throwing, more than once.
- **No new top-level destinations.** Anything new folds into Work or Designs.
- **Read the governing document first.** The first draft of this plan was
  written without reading the audit it claimed to follow, and missed the
  scorecard entirely as a result.
- **Something found broken mid-phase is written down here** and fixed in the
  phase it belongs to.
