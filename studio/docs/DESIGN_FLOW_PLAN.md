# The design flow: a phased plan

**Status:** agreed 2026-08-14. Rewritten after reading `docs/shirtfaced-audit.md`,
which the first draft of this file did not do. It is anchored to that audit's
Hot List (10 August) rather than to a parallel scheme of its own.

Two audits exist and both are used here:

- **`docs/shirtfaced-audit.md`** — the repository audit. Owns *what is missing*
  and the exit tests. Its Hot List numbering is used throughout below.
- **the Studio architecture audit @ b52354ec** — owns *how the screens are
  arranged*: consolidation, the production spine, the approval inbox, the
  five-destination navigation. Used where it serves a Hot List item, never
  ahead of one.

---

## The rule everything is judged against

> At every point there is **exactly one obvious next action**. Doing it reveals
> the next. Following that chain to a finished design requires no knowledge of
> which screen owns what.

The audit's closing note says the same thing from the other end: every system
here is built to a high standard *in isolation*, with scope statements that stop
it touching the others, and nothing stands above them saying how they connect.
The rule above is that missing thing, expressed as a test.

## The conflict that has to be settled first

Hot List #1 requires a design **"generated by this app"** — `design_generator.py`
producing artwork. The standing cost decision is the opposite: paid
subscriptions to OpenAI, Gemini and Anthropic already exist, an API key bills
separately, and generation must not be wired to one.

Both cannot hold. The proposed reading, which needs a yes or no before Phase 1
starts:

> The app owns the brief, the prompt, the record, the measurement, the judgement
> and the decision. The pixels are made outside it, in a paid UI, and brought
> back. Hot List #1 is met when a design has been carried through this app's
> pipeline and persisted with a decision — not when this app rendered the
> pixels.

If that reading is rejected, Phase 1 needs local generation first and everything
shifts behind it.

## Phase 1 — Hot List #1: one design, end to end, with a persisted decision

The audit's Phase 2 exit test, unmet since 7 August. Everything below exists to
make this possible; nothing else is started until it passes.

**What is missing, verified by tracing the code today, not assumed:**

1. **Artwork cannot be attached.** `uploadAsset()` exists in `api/concepts.ts`
   and no screen calls it. `Send to design pipeline` opens a `DesignAttempt` in
   `PLANNED` and there is no way in the application to give it an image.
2. **The nine judgement categories cannot be filled.** `design_extraction.py`
   correctly measures one and leaves nine `NOT_TESTED`. There is no form for a
   human to answer them, so `score_design()` can never receive a complete
   `DesignReviewInput`.
3. **Compositing is not in the path.** `print_design()` needs a hand-dragged
   quad and is reached from a different screen with no link from the attempt.
4. **Nothing says what is next.** No screen tells you the attempt is waiting.
5. **Research pre-selects an old run**, so ten historical concepts appear on
   load looking freshly generated.

**Exit test — the audit's own, run and pasted:**

> One real design carried from concept to a persisted decision through this
> app: attempt → artwork attached → composited onto a garment → measured →
> nine categories answered by a human → scored → decision stored. Done by
> someone who has not used the tool, without being told which screen to visit,
> without a terminal.

## Phase 2 — Hot List #2: which design belongs to which world

The audit: *"the single largest remaining structural disconnect in the repo."*
The constitution formally refuses this by its own scope statement, so nothing
owns the link from a design to a world, or from a post to a cart item.

This is where the Studio audit's **production spine** earns its place — not as
an architectural preference but as the thing that carries the link. One record
tying design concept, research provenance, attempt, approved version, and the
world it belongs to, with a derived `next_action`.

Derived, never stored twice: state comes from rows that already exist, so it
cannot drift from them.

**Exit test:** for any design, one call returns which world it belongs to and
what to do next, and both match what the screens show.

## Phase 3 — One screen that asks the question

**Work** replaces the current Dashboard: production items, each showing its next
action as a button that goes straight there. The Studio audit's approval inbox
folds into this rather than becoming a sixth island.

**Exit test:** the entire Phase 1 flow can be driven from Work without touching
the top nav.

## Phase 4 — Consolidate the design journey

Studio audit: Designs becomes the one screen, Compose becomes a generation
method within it, Score becomes an evaluation panel within it. Both leave the
top nav; their services stay put. The duplicate is the journey, not the code.

**Exit test:** two nav entries removed, no capability lost, Phase 1 still passes.

## Phase 5 — Hot List #3 and #5

**#3 — migrate `taglines.ts` to derive from `BRAND_VOICE.md`.** Flagged as open
in the canon document's own §9, and the exact failure mode that produced the
original brand-voice gap.

**#5 — a design generator.** Everything in System B still only evaluates work
that exists. `design_advisor.py` prescribes presentation and says outright it
will not invent artwork. Under the cost decision this means the *concept*
generator — which is what the vintage research bench already is, and it should
be recognised as that rather than left as a side branch.

## Phase 6 — Evidence reaches generation

Vintage evidence images inform the prompt text and never reach the image
generator; they are stored on the attempt as provenance only. The
`ReferenceImageStore` adapter exists and runs in production for photography.

Blocked on the same cost decision: doing this properly probably means local
generation. Raised, not assumed.

## Not started before Phase 3 passes

Hot List #4 (product-incidental vs product-photography — a written creative

## How this gets worked

- **One phase at a time, in order.** No starting the next because the current
  one is awkward.
- **Every phase ends with its exit test run and pasted**, never asserted.
- **Nothing ships without being exercised in a browser.** Server checks have
  passed while a screen was throwing, more than once.
- **No new top-level destinations.** Anything new folds into Work or Designs.
- **Something found broken mid-phase is written down here**, and fixed in the
  phase it belongs to.
- **Read the governing document before building.** `CLAUDE.md` requires naming
  the document that governs the work first. The first draft of this plan was
  written without reading the audit it claimed to follow.
